# スプレッドシート見切れ防止

Google Sheets をスマホで見る前提で、列幅・行高を文字量から決め、見切れ（文字が途中で切れる・はみ出す）を防ぐためのルール集。

## 基本姿勢

- 見積もりは小さくしない。迷ったら広めに取る。
- 計算の対象は「表示される文字列」: 数値はカンマ・小数点・％記号込みの表示形、日付は実際に表示される形式（yyyy/mm/dd）の文字列で数える。
- 列幅は「ヘッダー」と「全データ行の最長値」の両方を見て、大きい方に合わせる。

## セル内の改行

- セル内に複数の文や箇条書きを書くときは、「。」ごと・項目ごとにセル内改行（\n）を入れる。文をスペースや読点だけでつないで1行に詰め込まない。
- 行高は改行後の実際の行数に合わせて調整する。

## 列幅の計算（フォント11px）

- 必要幅の計算と検査は `width_check.py`（このスキルフォルダ）が行う。列幅メタデータとセル書式を JSON で渡すと、幅不足と日付書式の違反を一覧で返す。係数の正本は sheet-writer tool 側の Measures で、このツールの既定値は正本と整合するようテストで担保している
- 要点: 全角1文字 ≒ 11.5px、半角1文字 ≒ 6.3px（太字は全角 ≒ 12px、半角 ≒ 6.6px）。余白 +20px を必ず足し、切り上げる。日付書式は `yyyy/mm/dd`

### 実績値（電気料金の記録シート）

| 用途 | 幅 |
|---|---|
| 期間列（`2026/09/20～2026/10/19` の21文字） | 180px |
| 日付列（`2026/10/30`） | 108px |
| 使用月分列（`2026年9月～10月分`） | 136px |
| 備考列（折り返し） | 300px |

タブ別の最終列幅は各シートのメタデータが正（電気料金シート: `workspace/goals/goal-2/hidden_files/electricity-sheet.json`、タバコ: `workspace/goals/smoking/hidden_files/smoking-sheet.json`、日記: `workspace/goals/diary/hidden_files/diary-sheet-format.md`）。列幅を変えたらメタデータ側も必ず更新する。

## 行高

- 標準のデータ行: 26px
- ヘッダー行: 38px
- 折り返し列（300px幅の備考など）がある行は、文字量で決める: 約26文字まで 24〜26px、約52文字まで 40〜42px、それ以上 56〜58px

## 新規行を追加したら、上の行と必ず diff チェックする

新規追加行は書式・数式の付け忘れが起きやすい（実例: 水道の新規行で前回比の数式と振替日の日付書式が欠落、売電の新規行で備考が右寄せになっていた）。追加直後に以下を上の行と比べて確認する:

1. **背景色**: 明示設定されているか＋交互色のパリティ（偶数行 #FFFFFF / 奇数行 #EAF4EC）。effectiveFormat の白と「未設定（デフォルト白）」は見た目が同じでも別物なので、userEnteredFormat の設定有無まで見る
2. **配置**: 備考は左寄せ、数値は右寄せ、日付・期間は中央寄せ
3. **数値書式**: 金額 `#,##0`、使用量 `#,##0.0`、割合 `0.0%`、日付 `yyyy/mm/dd`（`yyyy/m/d` の混入禁止）
4. **数式**: 前月比・前年同月比などの差分列に数式があるか。金額未確定の保留行には `=IF(B12="","",B12-B11)` のように空欄ガード付きで入れておく（ガード無しだと 0 やマイナス値が表示されてしまう）

## 検証

- 列幅を変えたら `columnMetadata` を読み戻して、意図した幅になっているか確認してから報告する
- 「表の範囲」を疑われたら、テーブル・フィルター・交互色の範囲設定の有無も確認する（対象のシートはセルごとの塗り方式で、範囲設定は存在しないのが通常）
